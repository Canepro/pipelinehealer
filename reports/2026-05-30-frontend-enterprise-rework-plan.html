Where we actually are

Solid base, not the rework

The work to date is a correct design-token consolidation plus targeted accessibility and layout fixes: unified --ph-* tokens, fixed primary-button hover and focus rings, bound form labels, reduced-motion support, Control Center stat tiles + segmented tabs + a status strip, and a Settings secrets grid. That is good engineering hygiene and a real step up.

It is not yet enterprise-grade because the rework is partial and unvalidated: the ~3,300-line AdminControlsForm.tsx is only retokenized, the Dashboard / Activities / ActivityDetail flows got tokens but no redesign, there is no documented design-system foundation, and nothing has been validated for contrast (axe), keyboard, screen reader, responsive breakpoints, cross-browser, or real backend data.

Release path

Do not ship the rework inside PR #181

PR #181 is "prepare v0.8.0 production release." A multi-phase rework with a large, evolving diff does not belong in a release PR.

Recommendation: land the current token pass + the two committed redesign commits in v0.8.0 (it is green and a clear improvement), and run this rework as a separate tracked epic on its own branch, targeting v0.9.0.

Foundation

Design system (Phase 0)

Everything else depends on this. Define the scales as tokens in index.css + Tailwind config, build a small set of primitives, and document them on an in-app /styleguide route so usage stays consistent.

Tokens and scales

SystemDefinitionNotes for an ops console
Color rolesSurface elevation (page/panel/raised/overlay), semantic status (ok/warn/bad/info/neutral) with text+bg+border, and a fixed categorical data-viz palette.Dark-first. Status is load-bearing, so contrast must pass AA on every surface.
Type scaledisplay, page-title, section, label (11px uppercase tracked), body-sm, value, and a mono role for IDs, counts, durations, hashes.Dense consoles lean on monospace for technical values and tabular numerals.
Spacing4-point scale; fixed panel padding (compact 12/16, comfortable 20/24) and a density toggle.Grafana-style density: tighter default than a marketing app.
ElevationTokenized shadows per layer; today shadows are ad hoc.Subtle. Panels separate by hairline + faint shadow, not heavy drop shadows.
Radiussm 6 / md 8 / lg 12; pick one per component class and stop mixing rounded-md/lg/xl.Consistency reads as "designed."
