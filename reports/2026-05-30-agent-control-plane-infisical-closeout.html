Verdict

PipelineHealer is now an agent-control-plane baseline Complete

Detection and diagnosis remain owned by PipelineHealer. Selected failures can now be delegated to Codex App Server, OpenClaw, Hermes, or a custom target through durable HandoffSession and HandoffMessage records. External agents can report back through signed callback events, and PipelineHealer keeps the activity audit, labels, GitHub references, and verification trail.

Codex App Server is separate in two places: it can be selected as LLM_PROVIDER=codex_app_server for model-backed diagnosis/remediation work, and it can also be selected as an external handoff target for tool-backed work through connected runtime tools such as GitHub.

The current branch was deployed to Azure Container Apps with ACR remote builds and ACA secret refs populated from Infisical-injected process environment.

Residual risk

Known boundaries

  • Codex App Server integration is implemented against the JSON-RPC contract and verified by static/unit tests, but no live Codex App Server remediation run was executed in this closeout.
  • OpenClaw and Hermes are modeled as external handoff targets with callback contracts. Their receiver implementations still need to honor the documented payload and signature contract.
  • The ACA deployment has a custom handoff webhook configured. Named target-specific URLs for Codex App Server, OpenClaw, and Hermes remain unset until those receivers are ready.
