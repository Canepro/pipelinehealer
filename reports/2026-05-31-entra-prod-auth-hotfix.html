Production access control hotfix

PipelineHealer Entra production auth regression closeout

A production regression caused anonymous access to /api/stats through frontend proxy behavior. The hotfix re-enabled Entra auth mode in production runtime config, removed insecure proxy key injection in that mode, and aligned frontend and backend settings through deploy scripts and infra. Anonymous direct and proxy access now return 401, and the fix has been released and deployed to production as v0.8.2.

What is now true

Core access gap fixed

Production rollout is complete. The previous anonymous path issue from VITE_AUTH_MODE="none" has been corrected with production runtime now set to VITE_AUTH_MODE=entra and backend configured as AUTH_MODE=hybrid.

Backend and frontend images for v0.8.2 have been imported into production ACR and deployed. Final production health is healthy, version 0.8.2, environment production, and storage_backend cosmos_db. Both anonymous endpoints, https://pipelinehealer.canepro.me/api/stats and https://api.pipelinehealer.canepro.me/api/stats, now return 401 without credentials, while Entra and break-glass/admin paths remain functional.

Changes

Hotfix implementation footprint

Frontend runtime behavior

frontend/entrypoint.sh now conditionally omits proxy API auth header in Entra mode. frontend/nginx.conf uses API_PROXY_AUTH_HEADER to gate header injection correctly.

Infra and deployment flow

scripts/deploy/redeploy_azure_containerapps.sh binds a disabled non-secret placeholder in Entra mode, while infra/main.bicep and infra/main.prod.bicepparam carry Entra runtime settings.

Validation and release metadata

Tests were updated in backend/tests/test_redeploy_azure_env_sync.py, and release metadata was aligned for v0.8.2. Final Infisical prod path injection now reports 45 names, including Entra runtime keys.

Release and deployment
