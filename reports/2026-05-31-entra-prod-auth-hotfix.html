Outcome

What is now true

Core access gap fixed

The production frontend runtime config was accidentally set to VITE_AUTH_MODE="none", so Entra login was skipped. This created a serious access control issue because frontend proxying could pass an injected backend API key and return 200 from https://pipelinehealer.canepro.me/api/stats anonymously.

Live mitigation is now in place. Backend ACA is configured with AUTH_MODE=hybrid plus Entra validation values, and frontend ACA uses VITE_AUTH_MODE=entra. API proxy auth header injection is now disabled in production via non-secret placeholder behavior. The runtime configuration now reports Entra mode. Both anonymous frontend proxy /api/stats and unauthenticated direct /api/stats now return 401. Infisical break-glass key and admin checks still work.

Recommended next action

Finish release controls, then deploy

Prioritize PR merge and CI completion first, then tag v0.8.2, run release workflow, deploy the hotfix, and perform the final post-deploy smoke pass against production endpoints.

Changes

Hotfix implementation footprint

Frontend runtime behavior

frontend/entrypoint.sh now conditionally omits proxy API auth header in Entra mode. frontend/nginx.conf uses API_PROXY_AUTH_HEADER to gate header injection correctly.

Infra and deployment flow

scripts/deploy/redeploy_azure_containerapps.sh binds a disabled non-secret placeholder in Entra mode, while infra/main.bicep and infra/main.prod.bicepparam carry Entra runtime settings.

Validation and release metadata

Tests were updated in backend/tests/test_redeploy_azure_env_sync.py, and release documentation metadata was updated for v0.8.2. Infisical prod path now injects 44 names, including 12 Entra runtime names.
